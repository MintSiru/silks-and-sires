# 유럽 경마 시뮬레이션 기획서 (가제: Silks & Sires)

Oct 11, 2026 · @Siru

## 1. 개요

플레이어는 유럽의 작은 오너-브리더(owner-breeder)로 시작해 수십 년에 걸쳐 클래식 우승마와 부계(sire line)를 남기는 경마 왕조를 세운다. 위닝 포스트의 장기 경영·혈통 계승 구조를 뼈대로, 더비 스탈리온의 '한 마리를 직접 키우는' 손맛을 붙이고, 무대를 영국·아일랜드·프랑스 중심의 유럽 평지 경마로 옮긴다.

**플레이어 역할:** 마주(owner) + 생산자(breeder). 조교는 직접 하지 않고 외부 조교사(trainer)의 야드에 말을 맡기되, 조교 방침·출주 계획·기수 선택에 개입한다. 이는 유럽의 실제 관행과 두 원작의 중간 지점이다.

**네 가지 설계 원칙 (요청사항 반영)**

1. **방향성:** 위닝 포스트의 '시대를 건너는 경영', 더비 스탈리온의 '배합→육성→레이스' 몰입 루프를 모두 유지한다.
2. **가상화:** 국가명과 종마(씨수말) 이름만 실명, 경마장·레이스·사람·마주·생산목장·세일 회사는 모두 가상.
3. **경주 그래픽:** 첨부 이미지처럼 측면 띠(strip) 위에 번호 원판이 움직이는 2D 중계. 좌측 코스 미니맵, 우측 상위 순위 패널.
4. **유럽 시스템:** 그룹 레이스 체계, 공식 레이팅과 핸디캡, 마장(going) 7단계, 게이트 추첨(draw), 세일 시장, 종마 비즈니스를 핵심 경제로 구현.

**목표 플랫폼(제안):** 웹 브라우저용 싱글플레이(TypeScript). Claude Code로 개발하기 가장 쉬운 형태이며, 이후 데스크톱 패키징이 가능하다.

## 2. 레퍼런스 분석: 더비 스탈리온 vs 위닝 포스트

더비 스탈리온은 '한 마리를 깊게', 위닝 포스트는 '왕조를 넓게' 만드는 게임이다. 본 기획은 위닝 포스트의 시간 축과 경영 규모 위에, 더비 스탈리온의 배합 퍼즐과 육성 긴장감을 얹는다. 최신작은 [위닝 포스트 10 2026](https://www.gematsu.com/games/winning-post-10-2026)(2026년 3월 26일 일본 발매)과 [더비 스탈리온 2](https://game.watch.impress.co.jp/docs/news/2140421.html)(2026년 9월 24일, Switch 2)이다.

| 항목 | 더비 스탈리온 | 위닝 포스트 |
| --- | --- | --- |
| 플레이어 위치 | 목장주 겸 마주. 생산·육성·출주를 직접 지휘 | 마주 겸 생산자(오너-브리더). 시대를 따라가며 경영 확장 |
| 시간 스케일 | 세대 단위지만 체감은 '1두의 경주 인생' 중심 | 수십 년. 1960\~2020년대 시나리오로 역사를 재현 |
| 핵심 재미 | 배합 이론(니크스, 인브리드, 모계 대물림)으로 강한 말을 '만들어 내는' 퍼즐 | 계통 확립·창시자 계보 등 장기 혈통 목표와 명마 역사 체험 |
| 육성 | 조교·컨디션 관리가 직접적이고 결과가 체감됨. 능력이 성장 과정에서 드러남 | 조교사에게 위임 비중이 큼. 개입은 방침 수준 |
| 레이스 | 관전 중심, 긴장감 연출이 강점 | 결과·이벤트 중심, 레이스 자체 개입은 적음 |
| 경제 | 목장 자금 관리. 최신작은 파산 없는 캐주얼 모드와 제한 자금 레거시 모드 제공 | 상금·세일·종마료가 얽힌 대규모 경제. 후반 자금이 남아돌기 쉬움 |
| 서사 | 담백. 말 자체가 주인공 | 비서·라이벌·인물 이벤트, 명마 상관도 등 드라마 요소 풍부 |
| 해외 | 최신작에서 미국 GI·지방 경마 추가로 확장 중 | 해외 원정·해외 목장 지원이 오래됨 |

**계승할 점**

- (DS) 배합 결과가 '이론으로 설명되는' 쾌감: 왜 이 조합이 강한지 플레이어가 추론할 수 있어야 한다.
- (DS) 숨겨진 능력이 성장하며 서서히 드러나는 정보 공개 구조.
- (WP) 수십 년 단위 목표: 부계 확립, 명문 모계 구축, 왕조 기록.
- (WP) 라이벌 마주와 인물이 있는 살아 있는 세계.

**개선할 점**

- 반복 작업 피로(DS): 주간 루틴을 자동화하는 '방침 위임'과 요약 리포트로 줄인다.
- 후반 자금 인플레(WP): 종마 시장 가격이 경쟁자 수요에 반응하게 하고, 유지비·세일 수수료로 돈을 회수한다.
- 불투명한 수치: 숨김 능력은 유지하되, 조교사 코멘트·레이팅·타임 등 '해석 가능한 단서'를 충분히 준다.
- 레이스 개입 부족: 출주 전 작전 지시(포지션, 페이스메이커, 차장 선택)로 의사결정 지점을 만든다.

## 3. 일본 경마 vs 유럽 경마

가장 큰 차이는 돈이 어디서 나오느냐다. 일본은 높은 상금이 경주마 가치를 떠받치고, 유럽은 상금이 낮은 대신 그룹 1 우승마가 종마가 되어 버는 종부료가 가치의 핵심이다. 따라서 이 게임의 경제는 '이겨서 상금'보다 '이겨서 혈통 가치'를 축으로 설계한다.

| 구분 | 일본 (JRA 중심) | 유럽 (영·애·프 중심) | 게임 설계 시사점 |
| --- | --- | --- | --- |
| 운영 주체 | JRA 단일 기구가 개최·마권·상금 운영 | 국가별 경마 당국이 규칙·레이팅 관리, 경마장은 개별 운영 | 국가별 규정 차이(출주 등록, 상금 배분)를 데이터로 분리 |
| 조교 | 미호·릿토 트레이닝 센터에 집중 | 조교사가 각자 사설 야드와 갤럽(조교장)을 운영 | 조교사마다 야드 시설·위치·성향이 다름 |
| 상금과 가치 | 상금 수준이 매우 높음 | 상금은 상대적으로 낮고 종마 가치가 압도적 | 은퇴 후 종마 전환이 최대 수익원 |
| 레이스 등급 | G1\~G3, 리스티드, 조건전(클래스) | 그룹 1\~3, 리스티드, 클래스 1\~7 핸디캡 | 공식 레이팅(OR)이 출주 가능 레이스를 결정 |
| 핸디캡 | 일부 중상 핸디캡 | 하위 레이스 다수가 레이팅 기반 핸디캡 | 레이팅이 오르면 부담중량도 오르는 딜레마 |
| 코스 | 대부분 평탄한 타원형, 잔디+더트 | 기복·직선 코스·좌우 회전이 제각각, 거의 잔디. 겨울엔 올웨더 | 코스 개성이 레이스 결과를 크게 좌우 |
| 마장 | 4단계(양·약간 무거움·무거움·불량) | 7단계(Firm \~ Heavy) 등 세분화 | 마장 적성이 핵심 능력치 |
| 게이트 | 枠番 8색 구분, 마번 | 마번(새들클로스)과 별도로 게이트 추첨(draw) | 그래픽은 마주 승부복 색으로 구분 |
| 기수 | 소속·프리 혼재, 단기 면허 외국인 기수 | 대형 마주의 전속(retained) 기수, 견습 기수 감량 | 전속 계약을 경영 요소로 |
| 거래 | 셀렉트세일 등, 한구좌 마주 클럽 문화 | 대형 세일(이유마·1세마·브리즈업·현역마) 시장이 매우 활발 | 연중 세일 캘린더와 경매 미니게임 |
| 시즌 | 연중 개최 | 잔디 평지 시즌은 봄\~가을, 겨울은 올웨더·장애 | 계절 리듬이 강한 캘린더 |
| 페이스메이커 | 드묾 | 같은 마주의 페이스메이커 기용이 흔함 | 출주 작전의 선택지 |

*위 내용은 일반적 특징 정리이며, 세부 규정 수치(감량 폭, 클래스 레이팅 구간 등)는 구현 단계에서 가상 규정으로 재정의한다.*

## 4. 핵심 게임 루프와 시즌 캘린더

1년은 52주 턴이며, 한 마리의 일생이 다음 세대의 배합으로 되돌아오는 순환이 게임의 뼈대다. 플레이어는 여러 세대의 말을 동시에 굴리므로 매주 여러 단계가 겹쳐 진행된다.

```
[1 배합·종부] ──▶ [2 출산·성장] ──▶ [3 세일 시장]
 2~6월, 실명 종마    1~5월 출생, 이유마   이유마·1세마·브리즈업
      ▲                                        │
      │                                        ▼
[6 은퇴·종마 전환] ◀── [5 레이스·레이팅] ◀── [4 조교사 위탁·데뷔]
 성적×혈통=종부료     잔디 3~11월, 겨울 AW    야드·성향·수수료, 2세 봄 데뷔
```

강조한 6단계(종마 전환)가 유럽 경제의 핵심이다. 레이스 상금보다 종부료가 큰 보상이 되도록 수치를 맞춘다.

**시즌 캘린더 (북반구 기준)**

- **1월:** 모든 말 나이 일괄 +1, 출산 시작, 올웨더 시즌
- **2\~6월:** 종부 시즌
- **3\~4월:** 잔디 평지 시즌 개막, 2세 데뷔 시작
- **4\~5월:** 브리즈업 세일, 3세 마일 클래식
- **6월:** 12펄롱 더비급 클래식, 여름 대형 개최
- **7\~9월:** 3세와 고마령이 맞붙는 G1, 1세마 세일 개막
- **10월:** 시즌 최고 G1 주간, 메이저 1세마 세일, 현역마 세일
- **11\~12월:** 잔디 시즌 종료, 이유마·번식 암말 세일, 연말 시상

## 5. 메커닉 상세

네 개의 시스템이 하나의 질문으로 이어진다: '이 말을 어떻게 최고 가치의 종마로 만들 것인가.'

### 5-1. 혈통·생산

- **배합:** 실명 종마 풀에서 씨수말을 고르고, 종부료(nomination fee)를 낸다. 인기 종마는 신청 경쟁과 거절(book full)이 있다.
- **배합 이론(DS 계승):** 니크스(부계×모계 궁합표), 인브리드(4×3 등 근친 효과와 위험), 모계 대물림(자가 번식 암말의 세대 누적 보너스), 활력·보완(약점 보완 배합).
- **유전 모델:** 능력치마다 부·모 기여 + 무작위 편차. 숨김 값 '잠재(ceiling)'와 '성장형(조숙/만성)'을 별도로 유전.
- **장기 목표(WP 계승):** 부계 확립(내 생산 종마의 자손이 일정 수 이상 그룹 우승), 명문 모계(블랙타입 기록), 왕조 연대기.
- **실명 종마 처리:** 시작 연도 기준 현역 종마는 실명으로 등장하되, 게임 내 능력치·자손은 가상 시뮬레이션 결과로 생성한다.

### 5-2. 육성·조교사

- **성장 단계:** 망아지 → 이유마 → 1세마(브레이킹) → 2세 데뷔. 각 단계에서 능력 단서가 하나씩 공개(DS 최신작의 '성장하며 드러나는 적성' 방향).
- **조교사 선택:** 야드 위치(가상 지역), 시설 등급, 성향(2세 조기 투입형 / 장기 육성형 / 스프린트 전문 등), 수수료, 수용 두수.
- **방침 지시:** 주 단위로 '강하게 / 보통 / 휴양', 목표 레이스, 거리·마장 테스트 요청. 세부는 조교사에게 위임하고 결과는 코멘트로 보고.
- **컨디션:** 피로, 부상 위험, 정신 상태. 과조교는 부상, 저조교는 컨디션 미달.

### 5-3. 출주·레이팅

- **공식 레이팅(OR):** 매 레이스 후 가상 핸디캐퍼가 갱신. OR이 출주 가능한 핸디캡 클래스와 부담중량을 결정.
- **레이스 체계:** 미승리전 → 핸디캡(클래스 1\~7) → 리스티드 → 그룹 3/2/1. 블랙타입(리스티드 이상 입상)이 혈통 가치에 직결.
- **출주 결정:** 등록 → 최종 출주 확인(declaration) → 게이트 추첨. 당일 마장 변화로 출주 취소(non-runner) 선택 가능.
- **작전:** 포지션(선행/선단/중단/후방), 페이스메이커 동반, 기수 선택(전속·프리·견습 감량).

### 5-4. 경제·세일·종마

- **수입:** 상금, 세일 판매, 종부료, 현역마 매각, 신디케이트 지분 판매.
- **지출:** 조교료, 목장 유지비, 종부료, 세일 수수료, 등록료, 운송비(해외 원정).
- **세일 캘린더:** 이유마 세일(겨울), 브리즈업(봄), 1세마 세일(늦여름\~가을), 현역마 세일(가을). 실시간 호가 경매 미니게임.
- **종마 전환:** 은퇴 시 종마 가치 = 성적 × 혈통 × 체형/외모 평가 × 시장 유행. 종부료 책정과 첫 시즌 자손 성적이 가치를 재평가.
- **은퇴 진로와 NH 시장:** 수말은 평지 / 겸용 / NH 종마 / 거세 중에서 진로를 고른다. 거리 프로필(speed·classic·middle·cup)에 따라 평지·NH 가치가 갈리며, 스테이어의 피는 딸을 통한 외조부 효과로 평지에 남는다. 상세: [stamina-and-nh.md](stamina-and-nh.md)
- **인플레 억제:** AI 마주의 입찰 경쟁, 인기 혈통의 유행 순환, 두수 증가에 따른 유지비 체증.

## 6. 레이스 시뮬레이션과 2D 중계 그래픽

레이스는 결정론적 시드 기반 틱 시뮬레이션으로 계산하고, 화면은 첨부 이미지 같은 측면 띠 그래픽 하나로 보여 준다. 같은 시드면 같은 결과가 나와야 재현·디버깅·리플레이가 가능하다.

### 6-1. 시뮬레이션 엔진

- **틱:** 0.1초 단위. 각 말은 진행 거리 x, 레인(내외 위치) y, 속도, 남은 스태미나를 가진다.
- **구간 모델:** 출발(게이트 반응) → 포지션 다툼 → 순항 → 스퍼트. 기수 판단 AI가 페이스와 스퍼트 개시 지점을 결정.
- **입력 변수:** 능력치(스피드·스태미나·순발력·근성·파워), 거리 적성, 마장 적성, 코스 적성(기복·좌우 회전·직선), 게이트 위치, 부담중량, 컨디션, 기수 능력.
- **트래픽:** 앞이 막히면 감속하거나 외곽으로 우회. 유럽식 대규모 직선 레이스에서는 무리가 둘로 갈라지는 현상도 표현.
- **결과 산출:** 착순, 착차(머리·목·길이 단위), 구간 타임, 레이팅 산출용 성적 지수.

### 6-2. 중계 그래픽 사양 (첨부 이미지 기준)

화면은 한 줄의 가로 띠로 구성하고, 세 구역으로 나눈다.

| 구역 | 첨부 이미지의 요소 | 이 게임의 구현 |
| --- | --- | --- |
| 좌측 정보 | 코스 미니맵(선두 위치 점), 코스 종류·거리, 경사, 선두 속도 | 가상 경마장 미니맵, TURF/AW + 거리(펄롱·미터 병기), 마장(GOOD TO SOFT 등), 선두 속도, 남은 거리 |
| 중앙 띠 | 번호 원판이 진행 방향 화살표와 함께 이동, 세로 위치는 내외 레인 | 같은 방식. 원판 색은 枠番 대신 **마주 승부복 주색**, 테두리로 내 말 강조 |
| 우측 순위 | 상위 3두 마번·승부복·오즈, 레이스명·경마장명 | 상위 3두 + 착차, **분수 오즈(5/2 등)**, 가상 레이스명·등급 배지(G1 등) |

**표현 규칙**

- 원판 지름 고정, 겹치면 뒤쪽 말을 살짝 반투명. 번호 대비가 낮은 색은 테두리를 자동으로 바꾼다.
- 카메라는 선두\~최후미 범위를 따라 자동 줌. 결승 200m부터 상위권 확대.
- 결승 후에는 같은 띠 위에서 착차 표시와 사진판정 연출.
- 2배·4배 배속, 결과만 보기 옵션. 그래픽은 Canvas 2D로 구현하며 3D는 사용하지 않는다.

아래는 띠 화면의 배치 시안이다(모든 이름은 가상).

```
┌──────────────────┬──────────────────────────────┬──────────────────────┐
│ 코스 미니맵 (●)  │ 진행 방향 →                  │ 상위 3두·착차·오즈   │
│ TURF 1,600m (8f) │       ⑥          ①      ③    │ ③ 선두         9/4   │
│ 마장 GOOD TO SOFT│  ④        ⑧         (⑦)      │ ⑦ ½ 마신       5/1   │
│ 남은 거리 2f     │        ②      ⑤    내 말     │ ① 목           11/2  │
│ 선두 속도 km/h   │ ──────── 내측 레일 ───────── │ Marlow Downs Mile G1 │
└──────────────────┴──────────────────────────────┴──────────────────────┘
```

원판의 가로 위치는 진행 거리, 세로 위치는 레일과의 거리다. 색은 마주 승부복, 굵은 링은 내 말이며 오즈는 유럽식 분수로 표기한다.

## 7. 가상화 가이드

실명은 국가명과 종마(씨수말) 이름 두 가지뿐이며, 나머지는 모두 생성 규칙에 따라 만든 가상 고유명사를 쓴다.

| 대상 | 처리 | 예시·규칙 |
| --- | --- | --- |
| 국가 | 실명 | 영국, 아일랜드, 프랑스, 독일, 이탈리아 + 원정지(일본, 미국, 호주, 홍콩, 두바이) |
| 종마(씨수말) | 실명 | 시작 연도에 현역인 종마 목록을 데이터 파일로 관리 |
| 경마장 | 가상 | 지형 원형(archetype)만 참고: 기복 큰 좌회전, 1마일 직선, 평탄 대형 우회전 등. 이름 예: Ashcombe, Marlow Downs, Saint-Ourens |
| 레이스 | 가상 | 클래식 구조(2세 마일, 3세 마일, 3세 12펄롱 더비급, 장거리 클래식)만 차용. 실제 레이스명·후원사명 금지 |
| 사람 | 가상 | 조교사·기수·마주·핸디캐퍼. 국가별 이름 생성기(성+이름 조합) 사용, 실존 인물과 동명 회피 |
| 생산목장·세일 회사 | 가상 | 예: Kilbeggan Vale Stud, Hollowmere Sales |
| 내 생산마·암말·라이벌 경주마 | 가상 | 등록 규칙: 18자 이내, 중복 금지 |
| 기관·규정 | 가상 | 국가별 가상 경마 당국, 가상 레이팅 기구 |

**주의:** 개인 프로젝트에서는 문제가 적지만, 공개·판매 시에는 일부 종마 이름의 상표·명칭 사용 문제를 별도로 확인해야 한다. 실명 종마 데이터는 이름 교체만으로 가상화할 수 있게 ID 기반으로 분리 저장한다.

## 8. 기술 구조와 개발 로드맵

엔진(순수 로직)과 화면(UI)을 완전히 분리한다. 엔진은 브라우저 없이 테스트로 검증되므로, Haiku가 만든 코드를 Opus가 테스트 결과로 검수하기 쉽다.

**기술 스택(제안):** TypeScript, Vite, React(메뉴·관리 화면), Canvas 2D(레이스 띠), Vitest(테스트), 저장은 IndexedDB + JSON 내보내기.

**폴더 구조**

```
/docs        기획서, 규칙 명세(spec), 결정 기록
/data        종마 목록, 가상 경마장·레이스·이름 사전 (JSON)
/src/engine  시간 진행, 혈통·유전, 육성, 레이팅, 경제, 레이스 시뮬레이션
/src/ui      React 화면, Canvas 레이스 뷰어
/tests       엔진 단위 테스트, 밸런스 시뮬레이션(1,000시즌 자동 진행)
```

**마일스톤**

1. **M0 기반:** 프로젝트 골격, 데이터 스키마, 시드 기반 난수, 주 단위 시간 진행.
2. **M1 레이스 코어:** 틱 시뮬레이션 + 2D 띠 뷰어. 가상 경마장 4곳, 마장 7단계. 완료 기준: 같은 시드 재현 100%, 레이스 1회 계산 50ms 이하.
3. **M2 말과 혈통:** 능력치·유전·성장, 실명 종마 데이터, 배합 화면.
4. **M3 시즌:** 레이스 캘린더, 출주 등록, OR 레이팅·핸디캡, AI 마주·조교사.
5. **M4 경제:** 세일 경매, 종부료, 종마 전환(평지·겸용·NH·거세), NH 스토어 세일 추상화, 유지비. 완료 기준: 30년 자동 진행 시 자금 인플레 없음, 컵 프로필 종마의 70% 이상이 NH·겸용 진로.
6. **M5 장기 목표·서사:** 부계 확립, 연대기, 라이벌 이벤트, 연말 시상.
7. **M6 다듬기:** 튜토리얼, 저장 관리, 밸런스, 성능.

**후속 확장 후보:** 장애(점프) 경마 레이스 화면(NH 시장 경제는 M4에서 선구현), 해외 원정 확대, 신디케이트·한구좌 마주.

## 9. Claude 작업 체계: Opus 기획·검수 / Haiku 실무

Opus는 명세를 쓰고 결과를 검수하며, Haiku 서브에이전트 셋이 구현·데이터·테스트를 맡는다. 프롬프트 키트(CLAUDE.md, 에이전트 정의 3개, 시작 프롬프트)는 대화창에 첨부한 zip 파일에 들어 있다.

| 역할 | 모델 | 맡는 일 | 하지 않는 일 |
| --- | --- | --- | --- |
| 총괄(메인 세션) | Opus | 기획 해석, 아키텍처·공용 타입, 티켓 명세, 검수, 통합, 사용자 보고 | 대량 구현(예외: 50줄 이하 통합 수정, 2회 반려 작업) |
| haiku-coder | Haiku | 명세 1건 구현 + 테스트 통과 | 공용 타입 변경, 명세 밖 파일 수정 |
| haiku-data | Haiku | 가상 고유명사, JSON 데이터, 실명 종마 목록 | 실명 사용(국가·종마 제외) |
| haiku-tester | Haiku | 단위 테스트, 시드 재현 검사, 밸런스 자동 시뮬레이션 리포트 | 구현 코드 수정 |

**티켓 사이클:** 명세(Opus) → 위임(Haiku) → 보고 양식 반환 → 검수(Opus가 테스트·타입체크·린트 직접 실행) → 승인 또는 반려. 같은 티켓이 2회 반려되면 Opus가 직접 고치거나 티켓을 더 작게 쪼갠다. 한 티켓은 파일 5개, 약 300줄 이하로 제한해 Haiku의 정확도를 지킨다.

**사용 방법**

1. zip을 풀어 `silks-and-sires` 폴더를 프로젝트 폴더로 쓴다.
2. 이 기획서를 Markdown으로 내보내 `docs/plan.md`로 저장한다.
3. 폴더에서 Claude Code를 열고 모델을 Opus로 고른다.
4. `KICKOFF_PROMPT.md`의 프롬프트 본문을 첫 메시지로 붙여 넣는다.
5. Opus가 M1까지 진행한 뒤 보고하면, 확인하고 다음 마일스톤을 승인한다.

에이전트 정의 파일은 `model: haiku`로 고정되어 있다. 세션 도중 만든 정의가 바로 인식되지 않을 때를 대비해, 프롬프트에 'Agent 도구의 model을 haiku로 지정하라'는 대체 지시도 넣었다.
