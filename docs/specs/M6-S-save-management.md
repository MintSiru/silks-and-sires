# M6-S 저장 관리

담당: Codex(gpt-6.1-sol, high) · 근거: 30년 저장 28MB(docs/reports/M5-G-30year.md), docs/m6-plan.md · 병렬: M6-P(엔진 성능)와 파일이 겹치지 않게 src/ui/storage·src/engine/save 위주

목적: 오래 플레이해도 저장·불러오기가 빠르고 안전하게, 여러 슬롯과 파일 내보내기를 지원한다.

## 범위
1. **크기 측정**: 30년 저장본(테스트로 생성)의 최상위 필드별 바이트를 표로(docs/reports/M6-S-size.md). 큰 필드의 보존 정책을 점검하되 게임 규칙은 바꾸지 않는다(보존 기간 축소가 필요하면 [질문]).
2. **압축 저장**: 브라우저 내장 `CompressionStream('gzip')`/`DecompressionStream` 으로 IndexedDB 에 압축 저장(새 의존성 금지). 지원하지 않는 환경(테스트의 fake-indexeddb 등)은 비압축으로 대체. 옛 비압축 저장본도 그대로 불러온다(형식 표시 필드로 구분).
3. **슬롯**: 수동 저장 슬롯 3개 + 자동 저장 1개(매 4주·연말 정산 뒤). 메뉴 › 저장·불러오기 창에 슬롯별 날짜·마주 이름·게임 날짜·크기. 덮어쓰기·삭제 확인.
4. **내보내기/가져오기**: 기존 fileTransfer(JSON 파일)를 압축 파일(.ssg — gzip JSON)과 일반 JSON 둘 다 지원. 가져올 때 schemaVersion 검사·마이그레이션(save/serialize.ts applyMigrations)·validateGameState 오류는 한국어로 표시.
5. **안전**: 저장 중 오류(용량 초과 등)는 한국어 안내 + 기존 저장 보존(쓰기 실패 시 이전 슬롯을 지우지 않음).
6. 테스트: 압축 왕복(지원 환경 모킹), 옛 저장본 불러오기, 슬롯 목록·삭제, 가져오기 오류 문구, 자동 저장 주기.

## 수용 기준
1. 30년 저장본 압축 크기 측정 보고(목표: 원본의 25% 이하).
2. 위 테스트 통과, 옛 저장본(현재 형식 JSON) 불러오기 회귀 없음.
3. 브라우저 스모크(tests/ui/ux2-shell.smoke.mjs)에 슬롯 저장·불러오기 추가 — 샌드박스에서 막히면 [질문](Opus 실행).
4. `npm test && npm run typecheck && npm run lint && npm run build` 통과.
