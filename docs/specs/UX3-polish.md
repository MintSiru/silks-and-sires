# UX3 다듬기: 재플레이 고칠 목록 + 스크롤 최소화

담당: Codex(gpt-6.1-sol, high — 기능 단위, UI 파일 여러 개) · 설계: docs/ux-plan.md '가독성 원칙'·'UX3 재플레이 결과' · 선행: UX2, UX4(번식 화면)

목적: Opus 재플레이(2026-10-16)에서 나온 고칠 목록을 반영하고, 사용자 요청 "화면 스크롤을 최대한 지양하는 디자인"을 모든 메뉴 화면에 적용한다.

## 기준
- 기본 창 1440×900 에서 각 메뉴의 첫 화면(하위 탭 기본값)이 **페이지 세로 스크롤 없이** 들어온다. 긴 목록은 높이 고정 표 안 스크롤·페이지 넘기기·접기로 처리한다. 좁은 화면(390px)은 세로 스크롤 허용, 가로 넘침 금지.
- 엔진은 이미 반영됨: 출주 계획 기본 '그대로 진행'(settings.autoApproveRacePlans 가 false 일 때만 승인제), 조건 목표 2주 유예. 엔진 수정 금지.

## 범위 (docs/ux-plan.md 'UX3 고칠 목록' 1~8)
1. 스크롤: 세일 일정은 앞으로 3개월 기본 + '전체 일정' 접기, 카탈로그·로트 상세는 옆 패널. 시작 화면은 2단(왼쪽 기본 설정, 오른쪽 승부복) 배치. 경주 캘린더 12주는 주별 한 줄.
2. 시작 화면 라디오·체크박스를 라벨 왼쪽 한 줄 정렬, select·input 다크 토큰(app.css 공통 폼 스타일).
3. 말 상세 개요 능력 등급 칩 대비(글자 색을 등급 색 토큰으로, WCAG AA 대비).
4. 경주 캘린더: 주별 한 줄 = 날짜 · 고정 일정 레이스(있으면 이름·등급) · 개최 경마장(나라) · 예상 종류 요약 · 내 말 계획 표시(말 이름 칩). 펼치면 세부.
5. 출주 계획 조건 표기: 거리 범위 대신 '약 1,700m 전후'(target 중간값, 100m 반올림), '클래스 5~5' → '클래스 5', 원정이면 '원정: 아일랜드'. 지난 계획(skipped·run)은 접어서 최근 3건. 상태 칩 문구: proposed 는 기본 진행 방식에서 '조교사 제안(진행 예정)', 승인제에서 '검토 대기'.
6. 홈: '이번 주 할 일'에서 출주 계획 제안 항목은 승인제일 때만. 대신 '이번 주·다음 주 내 출주 예정' 카드(계획·신청). '최근 결과'는 내 말 결과 우선(없으면 '내 말 결과 없음' + 주요 G1 결과 한 줄), '최근 이벤트'는 내 말 관련 이벤트만.
7. 마구간 경고 칸: '제안 검토'는 승인제일 때만. 기본은 '다음 출주' 열이 대신한다.
8. 2세마 계획이 비면 '2세 데뷔 가능: ○월 ○주부터'(config TWO_YO_FROM_WEEK 등 기존 상수 읽기) 안내. 3세 이상 계획이 비면 사유 한 줄(부상·조교사 미배정·맞는 레이스 없음).
9. 측정용 스모크 확장: tests/ui/ux2-shell.smoke.mjs 에 각 메뉴(홈·마구간·번식·경주·세일·목장·경영)에서 `document.documentElement.scrollHeight <= innerHeight + 4`(1440×900) 검사 추가. 실패하는 화면은 고친다. 결과 JSON 에 화면별 scrollHeight 를 남긴다.

## 수용 기준
1. 스모크: 1440×900 에서 7개 메뉴 기본 화면 세로 스크롤 없음, 390px 가로 넘침 없음, 콘솔 오류 없음(측정값 보고). 브라우저 실행이 막히면 [질문]에 적고 Opus 가 실행한다.
2. 위 2~8 항목을 순수 함수 테스트(뷰 모델: 조건 표기·홈 카드·마구간 경고·캘린더 한 줄 요약)로 확인.
3. `npm test && npm run typecheck && npm run lint && npm run build` 통과. 엔진 변경 없음.
