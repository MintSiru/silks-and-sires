# UI 검토 요청 (아스트라·아르곤에 보낼 지시문)

> 스크린숏 다시 찍기: `npm run screens` (빌드 후 docs/feedback/screens/ 갱신). 1차 검토는 아래 '1차 지시문', 고친 뒤 다시 볼 때는 맨 아래 '재검토 지시문'을 쓴다. 지난 검토 종합은 docs/feedback/ 의 날짜별 ui-review 문서.

아래 지시문과 함께 `docs/feedback/screens/` 의 스크린숏(파일 이름 = 화면)을 첨부해 주세요. 두 모델의 답을 그대로 돌려주시면 Opus 가 비교해 다듬기 티켓을 만듭니다.

---

당신은 게임 UI/UX 디자이너입니다. 첨부한 스크린숏은 웹 브라우저(1440×900)에서 도는 경마 경영 시뮬레이션 게임 'Silks & Sires' 의 화면입니다. 플레이어는 유럽 평지 경마의 오너-브리더(말을 생산하고 경주시키는 마주)로, 수십 년 동안 말을 사고·기르고·경주시키고·교배하며 왕조를 세웁니다. 게임 글자는 한국어입니다.

설계 원칙(이미 정한 것):
- 한 화면에 한 가지 일. 숫자보다 등급·한 줄 설명을 먼저.
- 같은 정보·버튼은 한 곳에만. 상태 색은 좋음·주의·위험 3가지.
- 1440×900 에서 각 메뉴 첫 화면은 세로 스크롤 없이 보여야 한다(긴 목록은 표 안 스크롤·접기).
- 3D·실사 이미지 없음. 다크 테마.

화면 구성: 위쪽 바(날짜·자금·진행 버튼·할 일·메뉴), 왼쪽 메뉴(홈·마구간·번식·경주·세일·목장·경영·기록), 말을 누르면 오른쪽 말 상세 창(개요·출주 계획·전적·혈통·기록).

부탁:
1. 화면마다 가장 거슬리는 문제 3가지(가독성·정보 위계·배치·일관성·조작 흐름), 각 문제에 구체적인 고칠 방법 1줄.
2. 게임 전체에서 처음 하는 플레이어가 막힐 곳 3가지와 해결책.
3. 시각 디자인(글꼴 크기·간격·색·대비·아이콘) 개선 5가지 — CSS 로 바로 옮길 수 있게 수치(px, 색 코드)로.
4. 이 장르(경마·스포츠 경영 시뮬레이션) 게임에서 잘된 UI 관례 중 우리 화면에 가져오면 좋을 것 3가지(구체적인 게임 이름이나 상표는 쓰지 말고 관례만 설명).
답은 한국어, 화면 이름별 제목 아래 번호 목록으로.

## 재검토 지시문 (고친 뒤 다시 볼 때)

아래 지시문과 함께 새 스크린숏(`docs/feedback/screens/`)과 지난 검토 종합 문서(`docs/feedback/2026-10-17-ui-review.md` 등 가장 최근 것)를 첨부해 주세요.

---

당신은 게임 UI/UX 디자이너입니다. 첨부한 스크린숏은 경마 경영 시뮬레이션 'Silks & Sires'(1440×900, 한국어, 다크 테마)의 화면이고, 첨부한 문서는 지난번 검토에서 나온 지적을 합친 목록(A~L, ★ = 우선)입니다. 개발팀이 이 목록을 보고 화면을 고쳤습니다.

부탁:
1. 목록의 항목마다 '개선됨 / 부분 개선 / 그대로 / 나빠짐' 중 하나와 근거 한 줄(스크린숏 파일 이름과 위치). 스크린숏으로 확인할 수 없는 항목은 '확인 불가'.
2. 고치면서 새로 생긴 문제(겹침·잘림·스크롤·대비·일관성) — 화면별 최대 3개, 각각 고칠 방법 한 줄(가능하면 CSS 수치).
3. 지금 상태에서 가장 먼저 고쳐야 할 것 5가지(우선순위 순).
설계 원칙(한 화면 한 가지 일, 등급·한 줄 설명 먼저, 같은 정보는 한 곳에만, 상태 색 3가지, 1440×900 첫 화면 세로 스크롤 없음, 3D·실사 이미지 없음)은 그대로입니다. 답은 한국어, 화면 이름별 제목 아래 번호 목록으로.
